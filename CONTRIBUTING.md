## 📝 Standards de code

Si vous souhaitez proposer des améliorations techniques :

### Structure des commits

```
type(scope): description courte

Description détaillée si nécessaire
```

Types acceptés : `feat`, `fix`, `docs`, `style`, `refactor`, `test`, `chore`

### Style de code

- TypeScript avec types stricts
- Commentaires en français
- JSDoc pour les fonctions importantes
- Nommage en anglais pour le code, français pour les commentaires
- Formatage avec Prettier (si disponible)

### Tests

- Tester localement avant de soumettre
- Vérifier que `npm run build` fonctionne
- Vérifier qu'il n'y a pas d'erreurs ESLint

## 🔐 Confidentialité

**Ne partagez jamais** dans les issues ou PRs :

- Clés API privées
- Tokens d'accès
- Informations personnelles sensibles
- Mots de passe ou secrets
